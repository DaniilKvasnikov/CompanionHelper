# TouchDesigner → CompanionHelper — гайд по API

> Это API, по которому **TouchDesigner обращается к CompanionHelper** (вкладка
> «Touch» на деке). Обратная сторона — нажатия кнопок на деке — уходит из
> CompanionHelper в TD одним OSC-сообщением; описание ниже.
>
> Всё в этом файле проверено на живом сервере (`POST` запросы к
> `127.0.0.1:7878` и перехваченный UDP-пакет OSC) и закреплено тестами
> `tests/test_touch.py`. Метки: `[verified]` — проверено запросом к серверу ·
> `[code]` — из кода (`core/touch.py`, `main.py`).
>
> Готовый шаблон клиента: [`touch/client.example.py`](touch/client.example.py).

---

## 1. Обзор

Вкладка «Touch» на деке — **пустая рамка**: своих кнопок у неё нет. Кнопки
присылает сам TouchDesigner, а сервер их рисует и проксирует нажатия обратно.

```
TouchDesigner ──POST /touch/buttons──▶ CompanionHelper ──OSC──▶ Stream Deck
              ──POST /touch/ping─────▶       (вкладка «Touch»)
              ◀────────OSC (id кнопки)───────  нажатие кнопки
```

| Что | Значение |
|---|---|
| База HTTP | `http://<адрес CompanionHelper>:7878` (`PORT` в `core/config.py`) |
| Транспорт | HTTP `POST`, тело — JSON (`Content-Type: application/json`), UTF-8 |
| Авторизация | нет |
| Обязательное поле | `client` — id клиента (латиницей, без пробелов) |
| Из TD в сервер | `POST /touch/buttons` (кнопки), `POST /touch/ping` (живость) |
| Из сервера в TD | одно OSC-сообщение на `host:port/address`, аргумент — строка с `id` кнопки |
| Таймаут клиента | `TOUCH_CLIENT_TIMEOUT = 30 с` без пинга → клиент уходит с деки |
| Конфиг | `TOUCH_OSC_HOST` / `TOUCH_OSC_PORT` / `TOUCH_OSC_ADDRESS` / `TOUCH_CLIENT_TIMEOUT` / `TOUCH_SWEEP_INTERVAL` в `core/config.py` (per-machine — `config.local.json`) |

Три правила, из которых следует всё остальное:

1. **Сервер ничего не спрашивает у TD.** Состояние на деке — ровно то, что
   прислал последний `POST /touch/buttons`.
2. **Список кнопок заменяется целиком.** Не «добавь/удали», а «вот актуальный
   список» — поэтому клиент просто переотправляет его, когда что-то изменилось.
3. **Пингом клиент продлевает себе жизнь.** Замолчал на 30 с — сервер выкинул
   его и перерисовал деку (закрытый `.toe` не оставляет мёртвых кнопок).

## 2. `POST /touch/buttons` — зарегистрировать клиента и его кнопки `[verified]`

Регистрирует клиента (или обновляет уже зарегистрированного) и **заменяет** весь
его список кнопок.

```json
{
  "client": "wall",
  "label": "Стена",
  "host": "127.0.0.1",
  "port": 7777,
  "address": "/touch",
  "buttons": [
    {"id": "intro", "label": "Intro"},
    {"id": "clipA", "label": "Клип A", "active": true},
    {"id": "black", "label": "Блэкаут", "color": "#4a1414"}
  ]
}
```

| Поле | Обяз. | По умолчанию | Смысл |
|---|---|---|---|
| `client` | **да** | — | id клиента; он же подпись подменю, если нет `label`. Пробелы по краям обрезаются (`"  x  "` → `x`), строка из одних пробелов = «не указан» |
| `label` | нет | = `client` | подпись подменю на деке; `"a\nb"` = две строки |
| `host` | нет | `TOUCH_OSC_HOST` (`127.0.0.1`) | куда сервер шлёт нажатия этого клиента |
| `port` | нет | `TOUCH_OSC_PORT` (`7777`) | порт OSC-приёмника в TD (число; строка `"7777"` тоже принимается) |
| `address` | нет | `TOUCH_OSC_ADDRESS` (`/touch`) | OSC-адрес нажатий (`/` в начале) |
| `buttons` | нет | `[]` | список кнопок клиента (см. §3) |

Ответ `200` `[verified]` — сколько кнопок принято **после** отбраковки строк:

```json
{"status": "ok", "client": "wall", "buttons": 4}
```

Ошибки `400` `[verified]` (это проверки самого обработчика; тело —
`{"detail": "<что именно не так>"}`):

| Тело запроса | Ответ |
|---|---|
| нет `client` (или пустая строка) | `400` `'client' (the client id) is required` |
| `port` не число | `400` `'port' must be a number` |
| `buttons` не список | `400` `buttons must be a list` |

Если тело запроса — **не JSON-объект** (массив, строка, битый JSON), до этих
проверок дело не доходит: FastAPI отвечает `422`
`{"detail":[{"type":"dict_type", ...}]}`. `[verified]`

`host`/`port`/`address` можно не слать вовсе — тогда нажатия уйдут на адрес из
конфига; удобно, когда TD и CompanionHelper на одной машине.

## 3. Кнопка: поля `[code]`

| Поле | Обяз. | По умолчанию | Смысл |
|---|---|---|---|
| `id` | **да** | — | то, что уходит в TD при нажатии (строка, как есть) |
| `label` | нет | = `id` | текст на кнопке деку; `"a\nb"` = две строки |
| `color` | нет | цвет «командной» кнопки из `COLORS` | фон, `#rgb` или `#rrggbb` |
| `active` | нет | `false` | `true` → кнопка горит зелёным (как «активное» состояние на других вкладках) |

Тонкости, которые легко не заметить:

- **`active` строго `true`** (JSON-булево). Строка `"true"` / `1` не считается —
  поле просто игнорируется.
- **`active` сильнее `color`**: активная кнопка всегда зелёная, свой цвет не
  показывается.
- **Плохой `color` не ломает кнопку**: строка не вида `#rrggbb` ⇒ в логе
  предупреждение `touch: ignoring bad color '...'`, кнопка рисуется цветом по
  умолчанию. `[verified]` — в логе сервера:
  `WARNING touch: touch: ignoring bad color 'красный'`.
- **Строка без `id` отбрасывается** с предупреждением, остальные кнопки
  принимаются; это не `400`, а «принято N кнопок» в ответе.
- `buttons: []` (или поле вовсе отсутствует) — валидная регистрация: клиент
  появится подменю, внутри будет пусто (только рамка деки: **Back**/**Home**).
  `[verified]` — `{"status": "ok", "client": "empty", "buttons": 0}`.
- `id` — произвольная строка (пробелы/кириллица допустимы), но именно она летит
  в OSC, поэтому удобнее латиница без пробелов: `intro`, `clipA`, `blackout`.

Порядок кнопок на деке = порядок в массиве `buttons`.

## 4. `POST /touch/ping` — живость `[verified]`

```json
{"client": "wall"}
```

| Ответ | Когда | Что делать клиенту |
|---|---|---|
| `{"status": "ok", "client": "wall", "buttons": 4}` | клиент известен, время жизни продлено | ничего |
| `{"status": "unknown", "client": "nope", "hint": "POST /touch/buttons first"}` | клиента нет в реестре (например, сервер перезапускали) | **переотправить** `POST /touch/buttons` |

Оба ответа — `200`: `unknown` это не ошибка запроса, а «зарегистрируйся заново».
Пустой `client` — `400` `'client' (the client id) is required`.

**Пинг никогда не регистрирует клиента** — иначе опечатка в id создавала бы
фантомное подменю. В логе сервера: `touch ping from unregistered client 'nope'`.

Частота: раз в 2–5 с (`PING_EVERY` в шаблоне = 5 с). Сервер проверяет клиентов
каждые `TOUCH_SWEEP_INTERVAL` (5 с) и выкидывает тех, кто молчит дольше
`TOUCH_CLIENT_TIMEOUT` (30 с) — то есть мёртвый клиент исчезает с деки в течение
~35 с. В логе: `touch client 'wall' dropped (no ping for 30s)`.

Рекомендуемый цикл клиента — «пинг, а если `status != ok` — отправить кнопки»:
это одновременно и живость, и восстановление после перезапуска сервера
(см. `pump()` в `touch/client.example.py`).

## 5. Нажатие кнопки: сервер → TouchDesigner (OSC) `[verified]`

Нажатие кнопки на деке сервер отправляет **обратно в TD** одним
fire-and-forget OSC-сообщением:

| Что | Значение |
|---|---|
| Куда | `host:port` клиента (или `TOUCH_OSC_*` из конфига) |
| Адрес | `address` клиента (по умолчанию `/touch`) |
| Аргумент | **один строковый** — `id` нажатой кнопки |
| Ответа | нет (подтверждения/подписки не существует) |

Перехваченный пакет для кнопки `intro` и адреса `/touch` `[verified]`:

```
2f 74 6f 75 63 68 00 00  2c 73 00 00  69 6e 74 72 6f 00 00 00
└─ "/touch" ───────────┘  └ ",s" ───┘  └─ "intro" ─────────────┘
```

То есть обычный OSC 1.0: адрес, тип-тег `s`, строка. В TD это ловит **OSC In
DAT** (или OSC In CHOP) на порту `port`; отдельная подписка не нужна — нажатие
приходит как входящее сообщение, разбирать которое удобно по адресу
`address`, а значение брать из первого аргумента (id кнопки).

Если клиент к моменту нажатия уже вылетел по таймауту, на кнопке деки
появится `ERR\nнет клиента` — OSC никуда не уйдёт.

Полезно знать:

- сообщение **не подтверждается**: потерянный UDP-пакет клиент не заметит.
  Если нужна гарантия — держите на стороне TD второй источник (например,
  кнопку на самой деве), либо шлите идемпотентные команды;
- нажатие **не меняет** кнопки на деке: чтобы после нажатия поменялась
  подсветка/подпись, клиент должен сам переотправить `POST /touch/buttons`
  с новым `active`.

## 6. Что видно на деке

- Один живой клиент = одно **подменю** на вкладке «Touch»; подпись —
  `label` (над id), порядок — по `label` (без учёта регистра), затем по `client`.
- Внутри подменю — кнопки клиента в присланном порядке; **Back**/**Home** и
  пейджинг (Prev/Next) рисует сам фреймворк, они не приходят из TD.
  `[code]` — единственные кнопки не от клиента.
- Если живых клиентов нет, вкладка показывает `Touch\nнет клиентов`.
- Вкладка «Touch» **одна на все деки** (`DECK_PAGES`): клиенты не привязаны к
  конкретной деке, поэтому два Stream Deck видят одни и те же подменю.

## 7. Минимальный клиент (Python внутри `.toe`)

Полный шаблон — [`touch/client.example.py`](touch/client.example.py); короткая
версия:

```python
import json, urllib.request

SERVER = "http://127.0.0.1:7878"      # адрес CompanionHelper
CLIENT = "wall"                        # id клиента
OSC = {"host": "127.0.0.1", "port": 7777, "address": "/touch"}

def post(path, payload):
    req = urllib.request.Request(SERVER + path,
                                 data=json.dumps(payload).encode("utf-8"), method="POST",
                                 headers={"Content-Type": "application/json"})
    with urllib.request.urlopen(req, timeout=5) as r:
        return json.loads(r.read().decode("utf-8", "replace"))

def pump():
    """Раз в 2-5 с: продлить жизнь, а если сервер нас не знает - заново прислать кнопки."""
    if post("/touch/ping", {"client": CLIENT}).get("status") != "ok":
        post("/touch/buttons", {"client": CLIENT, "label": "Стена", **OSC, "buttons": [
            {"id": "intro",  "label": "Intro"},
            {"id": "clipA",  "label": "Клип A", "active": True},
            {"id": "black",  "label": "Блэкаут", "color": "#4a1414"},
        ]})
```

В TD это Text DAT с кодом + Execute DAT (onFrameStart с таймером) для `pump()`, и
OSC In DAT на порту 7777 для приёма нажатий.

## 8. Диагностика

| Симптом | Причина / что смотреть |
|---|---|
| Вкладка «Touch» → `нет клиентов` | ни один клиент не зарегистрирован, либо все вылетели по таймауту. Проверьте, что клиент вообще шлёт `POST /touch/buttons` и пингует |
| Клиент появился и исчез через ~30 с | перестали приходить пинги (`pump()` не вызывается, `.toe` в паузе) |
| `400` на регистрации | смотрите `detail` в ответе — там точная причина; в логе сервера запрос с кодом виден строкой `"POST /touch/buttons HTTP/1.1" 400` |
| `422` на регистрации | тело запроса — не JSON-объект (массив/строка/битый JSON); в `detail` сказано, что именно не так |
| Кнопка есть, нажатие не приходит в TD | не тот `host`/`port`/`address` (или OSC In DAT слушает другой порт); проверьте, что порт в TD совпадает с `port` регистрации — сервер шлёт именно туда |
| Подпись кнопки устарела | сервер не спрашивает состояние: клиент должен переотправить список после изменения |
| Клиент пропал, но подменю осталось пустым | нажатие пришлось на момент, когда клиент уже вылетел — обновите список (переотправка кнопок вернёт его) |

Логи сервера: `INFO touch: touch client 'wall': 4 buttons -> 127.0.0.1:7777/touch`,
`WARNING touch: touch ping from unregistered client 'nope'`,
`WARNING touch: touch client 'wall' dropped (no ping for 30s)`.

## 9. Что НЕ реализовано (осознанные ограничения)

- **Сервер не опрашивает TD.** Деку показывает то, что прислал последний POST:
  клиент, который сам поменял состояние и не переотправил кнопки, оставит на
  деке устаревшую подпись/подсветку.
- **Нет подтверждения нажатий** — OSC fire-and-forget.
- **История не ведётся**: клиент либо живой, либо его нет.
- **Статус-страница (`/`) не показывает клиентов Touch** — только значения
  AOTO/PixelHue/PDQ/ПК.
